## 底盘使能状态机 (6.12d 重构后)

底盘是否输出动力, 由单一掩码 `disarm_flags` 决定: **三位全清(==0)才武装**。
每个停车来源只置/清自己那一位, 互不干扰; 任一位为 1 即锁定停车。

```
                       disarm_flags (uint8_t, 上电默认 = DISARM_UNCALIBRATED)
   ┌──────────────────────────────────────────────────────────────────────┐
   │ bit0 DISARM_UNCALIBRATED   置: IMU 未校准      清: IMU 校准完成        │ ← 1ms ISR
   │ bit1 DISARM_COMM_LOST      置: 看门狗>1000ms   清: 收到无人机下传数据  │ ← 主循环
   │ bit2 DISARM_MANUAL         置: 无线 ch8 == 1   清: 无线 ch8 == 0       │ ← 调参回调
   └──────────────────────────────────────────────────────────────────────┘

        ┌─────────────────────────┐   任一 Chassis_Block(reason)    ┌──────────────────────────┐
        │   ARMED (已武装)        │  ─────────────────────────────► │  DISARMED (锁定)         │
        │   disarm_flags == 0     │   置位→Chassis_Apply_Stop():    │  disarm_flags != 0       │
        │                         │   灭4路PWM/清6个PID/清视觉状态  │                          │
        │  · 跑斜坡+yaw串级+轮速  │ ◄───────────────────────────── │  · 电机输出强制 0        │
        │    PID, 驱动电机        │   最后一个 Chassis_Unblock 清零 │  · 控制环跳过电机赋值    │
        │  · Visual_Control_Loop  │   →复位PID+视觉状态, 干净起步    │                          │
        └─────────────────────────┘                                 └──────────────────────────┘

   幂等: Block 同一位重复调用→直接返回(杜绝1ms狂调); Unblock 仅在清零最后一位时才复位起步。

   关键安全路径 (本次修复的隐患):
     人工急停(ch8=1) ─置bit2─► DISARMED
        └─ 期间无人机断连 ─置bit1─► 仍 DISARMED (bit1|bit2)
              └─ 无人机重连 ─清bit1─► 仍 DISARMED (bit2 未清) ✅ 不会自动跑起来
                    └─ 人工解除(ch8=0) ─清bit2─► flags==0 ─► ARMED
```

8.9a
【本提交用于双向通讯调试，不用于正常运行】
板间通讯由原「单向接收」升级为「双向主从请求-应答」，小车为从机。
接收：解析无人机 CMD_MASTER 请求帧 (54 字节)，保留原有 NaN/Inf 与业务语义防御后写入 uart_data[12]。
应答：收到有效请求后置 reply_pending，由主循环 Board_Comm_Send_Reply() 回一帧 CMD_SLAVE
(18 字节，seq 回显，载荷 car_uplink_data[3] = IMU roll/pitch/yaw，后续前馈控制改传速度相关量)。
发送放在主循环而非中断，避免 RS485 的 DE 保持延时阻塞 1ms 底盘控制 ISR。
FIFO 内积压多个请求时只回最新一帧应答，与既有「只保留最新帧」语义一致，
因此主循环卡顿会表现为无人机侧的一次超时统计。
帧格式：0xAA 0x55 + cmd + seq + N*float + 累加校验 + 0x7F，校验范围覆盖 cmd 与 seq。
编译期开关 DUPLEX_SWITCH (car_board_comm.h) 置 0 可退回原单向协议，需与无人机端保持一致。
方向引脚沿用 P06_2 (MAX3485 DE 与 RE# 并接)。

调试过程中上行链路曾完全不通。定位手段与结论详见无人机端 README 的 8.9a 条目，
小车侧对应的两项改动：
1. 应答帧前置前导字节 (BOARD_TX_PREAMBLE_LEN)，用于吸收总线换向期造成的首字节错位。
   3 字节使丢包 4.48% -> 3.06%，8 字节配合 DE 建立时间加大后降到 0.31%。
2. BOARD_DIR_SETUP_US 由 20us 加大到 100us，把应答发送推后以绕开无人机 DE 多占总线的窗口。
   BOARD_TX_HOLD_US 由 200us 改为 20us：uart_write_buffer 返回时末位已完整发出
   (Cy_SCB_IsTxComplete 语义为 FIFO 与移位寄存器双双为空)，原 200us 属白等且延后总线释放。
真正的治本改动在无人机端 (其 TX_HOLD 200us -> 20us)，本端第 1、2 项属于从另一头绕开重叠，
故治本后可逐步退回：DIR_SETUP 可回 20us、前导可回 2~3 字节，退回时一次只改一个参数并实测确认。

验证结果 (65 秒 / 3252 帧)：接收与应答计数完全同步，每帧线上 26 字节 (8 前导 + 18 帧) 精确匹配，
校验和/帧尾/语义防御/命令字不匹配四项计数全程为 0。

本提交保留了诊断埋点与 printf 输出 (de 回读、txb 等)，其打印一行约 49 字节、阻塞主循环约 4.3ms。
注意主循环卡死看门狗 MAINLOOP_STALL_MS 仅 10ms，一次打印即占去约四成预算，
正常运行前需清理，详见仓库根目录 TOFIX.md 的 P0-1。
